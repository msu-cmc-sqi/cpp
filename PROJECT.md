# Итоговый проект

**Дедлайн сдачи и защиты — 20 декабря 2026 года включительно (московское время).** Финальный pull request со всем содержимым проекта должен быть отправлен в GitHub, а защита пройдена к этой дате.

[Урок 08](assignments/lesson08/README.md) содержит порядок работы с ИИ-агентом, требования к документации и развёртыванию, состав pull request и формат защиты. Выбрать тему можно из [каталога проектов](assignments/lesson08/PROJECT_IDEAS.md).

## Задание

Найдите на Hugging Face открытую модель и разработайте на C++ законченное локальное приложение, решающее прикладную задачу. Модель должна быть частью системы, а не заменять всю прикладную логику одним запросом.

Подходящие направления: анализ исходного кода или логов, помощник по локальной документации, извлечение структурированных данных, безопасная работа с SQLite, семантический поиск, протокол встречи или текстовая игра со строгим состоянием мира. Можно предложить собственную идею.

## Ограничения по оборудованию

- обязательный режим запускается на CPU;
- платные API и постоянное подключение к интернету не требуются;
- рекомендуемый формат модели — GGUF;
- рекомендуемый размер файла модели — не более 3 ГБ;
- модель и каталоги сборки нельзя добавлять в Git;
- ускорение Metal, CUDA или Vulkan является дополнительной возможностью, но не требованием.

Модель разрешается запускать через локальный `llama-server`. Основное приложение, прикладная логика и интеграция должны быть реализованы на C++.

## Минимальные требования

- C++17/20 и CMake;
- CLI с понятной справкой;
- конфигурационный файл без секретов и абсолютных путей;
- разделение прикладной логики, HTTP/JSON и работы с моделью;
- структурированный результат модели с проверкой формата;
- таймауты и обработка ошибок сети, JSON и модели;
- минимум 10 контрольных примеров;
- unit-тесты детерминированной части программы;
- измерение времени ответа;
- README с установкой, запуском и известными ограничениями;
- скрипт или точная команда скачивания модели.

Программа, которая только отправляет введённый текст модели и печатает ответ, не удовлетворяет заданию.

## Что описать при выборе модели

- ссылка на страницу модели и точное имя версии;
- решаемая задача и поддерживаемые языки;
- лицензия;
- размер и квантование;
- минимальные требования к памяти;
- ожидаемые достоинства и известные ограничения;
- почему эта модель подходит приложению лучше рассмотренных альтернатив.

## Что сдавать

```text
project/
├── CMakeLists.txt
├── README.md
├── config.example.json
├── include/
├── src/
├── tests/
├── examples/
└── scripts/
```

В репозитории должны находиться только исходники и небольшие тестовые данные. Итоговая версия должна собираться по инструкции на чистой машине.

Полный проект размещается в `assignments/lesson08/<фамилия>/` и сдаётся pull request в репозиторий курса. Кроме показанных файлов, добавьте документы по архитектуре, развёртыванию, проверкам и использованию ИИ-агента согласно [уроку 08](assignments/lesson08/README.md). Ссылки на внешний репозиторий или видео не заменяют код и документацию в PR.
