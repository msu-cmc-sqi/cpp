# Урок 2. ООП, полиморфизм и управление ресурсами

## Цель

Научиться проектировать небольшие иерархии классов, явно выражать владение ресурсами и безопасно использовать динамический полиморфизм.

## Основные темы

- интерфейс и реализация класса;
- абстрактные классы и чисто виртуальные функции;
- `override` и виртуальный деструктор;
- композиция вместо избыточного наследования;
- RAII и автоматическое освобождение ресурсов;
- `std::unique_ptr`;
- правило пяти, копирование и перемещение.

## Виртуальный деструктор

Если объект производного класса удаляется через указатель на базовый класс, деструктор базового класса должен быть виртуальным:

```cpp
class TextTransform {
public:
    virtual ~TextTransform() = default;
    virtual std::string apply(std::string_view text) const = 0;
};
```

Без виртуального деструктора такое удаление приводит к неопределённому поведению.

## Владение объектами

Для единственного владельца используется `std::unique_ptr`:

```cpp
std::vector<std::unique_ptr<TextTransform>> transforms;
transforms.push_back(std::make_unique<LowercaseTransform>());
```

Ручные пары `new`/`delete` в прикладном коде обычно не нужны. Объект должен освобождать принадлежащий ему ресурс в деструкторе.

## Копирование и перемещение

Если класс напрямую управляет динамической памятью, необходимо определить корректное поведение при:

- уничтожении;
- копирующем конструировании;
- копирующем присваивании;
- перемещающем конструировании;
- перемещающем присваивании.

В обычном прикладном коде предпочтительнее использовать стандартные контейнеры. В задаче `TokenBuffer` ручное управление памятью используется специально для изучения семантики владения.

## Использование ИИ

Использование AI-инструментов разрешено. Можно просить сгенерировать первоначальное решение, объяснить ошибку или предложить тесты. Перед отправкой необходимо проверить код и понимать:

- какой объект владеет ресурсом;
- где вызывается деструктор;
- чем копирование отличается от перемещения;
- почему базовому классу нужен виртуальный деструктор;
- что произойдёт на пустом вводе и на граничных значениях.

Принятое e-judge решение подтверждает совпадение результата с тестами, но не заменяет понимание программы.
