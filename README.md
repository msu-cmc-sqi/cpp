# Практикум C++: локальные AI-приложения

Полугодовой практикум для студентов 3-го курса. Мы повторим важные инженерные темы современного C++, а затем предстоит разработать собственное приложение, которое работает с локальной моделью с Hugging Face на обычном ноутбуке.

## Что будет в курсе

- Git, CMake и организация C++-проекта;
- современный C++17/20, RAII и стандартная библиотека;
- JSON, HTTP, конфигурация и обработка ошибок;
- локальные модели в формате GGUF и `llama.cpp`;
- embeddings, RAG, structured output и вызов инструментов;
- тестирование, измерение скорости и защита итогового проекта.

## Итоговый проект

Нужно найти подходящую модель на Hugging Face и создать законченное C++-приложение, в котором модель является одним из компонентов. Обязательная часть должна запускаться локально на CPU, без платных API и специализированной видеокарты.

Простой чат, который только пересылает текст модели, итоговым проектом не считается. Приложение должно решать прикладную задачу, иметь понятную архитектуру, обработку ошибок, тестовые сценарии и измерения.

Проект выполняется индивидуально. В конце семестра зачет с оценкой.

Подробности: [программа курса](course-program.md) и [требования к проекту](PROJECT.md).

## Использование ИИ

Использование инструментов ИИ при решении задач разрешено. На первых занятиях основной инструмент — чат: можно получать объяснения, генерировать первоначальный вариант кода, искать ошибки и подбирать тесты. Чат не видит локальные файлы и результаты запуска автоматически, поэтому в запрос нужно передавать условие задачи, относящийся к вопросу код, точный текст ошибки и проблемный тест. Предложенные изменения необходимо самостоятельно перенести в проект и проверить локально или в e-judge.

При переходе к большим проектам можно использовать агента, способного работать с файлами проекта, запускать сборку и тесты. Его действия и изменения также необходимо проверять.

Перед отправкой необходимо понимать устройство решения и быть готовым объяснить или изменить код на разборе.

Ответственность за корректность отправленного решения остаётся за автором. Статус `Accepted` в e-judge подтверждает прохождение тестов, но не заменяет понимание программы.

## Как сдавать задания

1. Сделайте fork репозитория курса.
2. Для каждого задания создавайте отдельную ветку.
3. Помещайте работу в `assignments/lessonNN/<фамилия>/`.
4. Не добавляйте в Git ключи, модели, каталоги сборки и другие большие файлы.
5. Отправляйте pull request с кратким описанием и инструкцией проверки.

Материалы первых занятий находятся в каталоге [assignments](assignments/README.md).
